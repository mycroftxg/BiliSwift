# BiliSwift 全应用整合待办

以 0.7.0 为审查基线。本清单记录同一能力在多个入口间不一致的问题及跨入口验收条件。既有任务与首页掉帧优先级继续见 [原待办](BACKLOG.md)。

## 0.7.1 实施进度

- 已修正音轨提示使用画质、切换超时误报成功和换视频后复用旧轨的问题。手动换轨失败会恢复原播放项，并尝试按目标画质刷新地址。高级格式真实片源、设备输出及故障注入验收待补。
- 已区分播放量缺失与真实零，隐藏缺失时长标记；视频详情头图使用详情数据，通知发件人与稿件作者分开。共享元数据缓存和历史分 P 跳转待补。
- 已让手动目录刷新绕过快照；搜索、详情等视图自身的刷新入口仍需接入。
- 已让动态评论和自带图片资源的直播消息复用评论正文。直播表情包查询、画面弹幕图片、输入选择器和真实直播回归仍待完成。
- 缩短头图淡入和播放器过渡。轮播退出时取消过渡，部分播放器动画遵循系统的减少动态效果设置；帧时间和完整视觉验收待补。

## P0 · 直播与评论内容一致性

- [ ] **保留直播表情数据。** 当前 `LiveChat.parse` 只输出用户名、文字和颜色，`LiveMessage` 没有表情字段，实时评论把空表情映射交给 `CommentTextView`。核对实际直播包，保留官方表情资源与标识。区分消息自带资源、需要表情包查找的标记和无法识别的普通文本。用截图中的 `[大笑]`、文字混排和独立表情回归。
- [ ] **让普通评论、动态评论、直播评论和屏幕弹幕共用表情解析。** 动态评论正文仍用纯文本；画面弹幕用 Canvas 直接绘制文字。共享文字和表情的解析结果、资源缓存及失败回退，列表沿用内联正文组件，Canvas 继续使用自己的渲染并按图片实际宽度安排轨道。验收加载失败、快速滚动、全屏和密集消息。
- [ ] **修正表情图的复用和刷新。** 现有正文任务只按文字重启，加载完成只比较图片数量。同一段文字收到新的表情映射时可能继续显示旧图。按表情标识与资源地址缓存和刷新，离屏时取消过期任务，避免相同表情在不同评论行里重复缩放。

## P1 · 评论能力从入口到结果统一

- [ ] **共用评论会话和单条评论状态。** 视频详情和播放器分别创建 CommentStore，详情和侧栏采用不同评论行。按账号、评论目标类型和 ID 共享评论数据、发送结果、点赞和回复更新。每个视图自行保留滚动位置与展开状态。验证从详情打开播放器、发送回复、关闭侧栏再返回详情。
- [ ] **共用输入区、表情选择器和发送反馈。** 将顶层评论、楼中楼、动态评论、弹幕和直播发言接入共享输入控件，按场景加载 B 站支持的表情。直播侧栏可直接发言，沿用现有直播提交链路。发送失败保留草稿，切房或换账号时隔离草稿和反馈。输入聚焦时压住播放器快捷键。
- [ ] **补齐评论排序和分集切换。** 普通视频已接入热度、时间，影视与动态仍需按各自评论资源使用同一排序控件和分页规则。直播保留到达顺序。验证影视换集、动态换帖、排序切换后，旧响应不覆盖当前列表。
- [ ] **复用评论正文、媒体与样式。** 视频详情、播放器、影视和动态对图片、表情、作者、回复计数和展开的支持存在差异。统一基础评论行，按接口能力显示操作。直播评论沿用相同字体与状态样式，上翻历史时保持位置，提供回到最新消息的入口。

## P1 · 扩展到全应用的信息一致性

- [ ] **统一导航身份和详情解析。** 视频路由目前用 BV 字符串是否以 `ss` 开头选择影视详情，播放层却另有影视字段。让导航和播放共用内容类型、季 ID 和单集 ID 判断。用同一部正版影视从首页、分区、搜索、动态和收藏进入，核对详情、封面与播放集一致。
- [ ] **统一跨页面的点赞、收藏与关注状态。** 播放器与详情分别读取和保存点赞，搜索结果和 UP 主页各自持有关注状态。按账号及资源身份共享并更新对应字段。验收三连部分成功、关注后返回搜索、登出与账号切换。
- [ ] **修复工具栏刷新按钮无效。** 用户反馈点击后没有效果。当前按钮对消息单独处理，其余走目录加载，且目录加载可能直接命中新鲜快照。让手动刷新绕过快照并刷新当前可见页面的数据，保留筛选及阅读位置，显示加载和失败重试状态。验收首页、观看历史（云端与本机）、搜索、UP 主页、关注、详情、动态和消息；验证缓存有效时点击、连续点击与刷新中切页。

## 跨入口验收

- [ ] **建立功能矩阵。** 对视频详情、播放器侧栏、影视、动态、直播评论及屏幕弹幕逐一核对文字、表情、发言、回复、排序、刷新和账号切换。明确各场景支持的操作。至少用普通评论、图文动态和一间有表情消息的真实直播做端到端回归。
- [ ] **验证整合后的性能和界面。** 在首页惯性滚动、长评论、直播消息高峰、侧栏展开、窄窗口和全屏场景检查帧时间、滚动位置和文字对比度。用实际素材验证表情下载和渲染不会阻塞视频或弹幕。

## P1 · 第二轮审查：播放入口、资料库与楼中楼

- [ ] **统一恢复与暂停播放的入口。** 工具栏“继续播放”、详情页恢复和退出沉浸播放部分直接调用 AVPlayer，迷你播放条和系统媒体键走 PlaybackController。让这些入口共用播放状态更新、进度保存和系统媒体信息刷新。验证暂停后返回详情、从迷你条展开、直播恢复和换集后的状态一致。
- [ ] **让历史记录找回原来的分 P。** 云端历史目前只保留普通稿件并将条目转换成 Video，本地历史列表也会把含 CID 与进度的记录转换成 Video。为历史条目保留原分 P 或单集身份及进度，明确云端与本地数据的恢复优先级。验证从历史页能回到上次观看的分 P，并核对正版影视是否有可用的云端历史数据。
- [ ] **同步详情操作与资料库列表。** 详情页加入稍后再看后只显示操作结果，资料库有独立快照。将稍后再看和收藏夹的增删同步到对应列表或标记其快照过期，验证立即切页、重复添加、操作失败和账号切换。
- [ ] **统一楼中楼的分页和发送后刷新。** 视频详情按页加载子回复，播放器侧栏只请求一批。详情的回复弹窗成功后直接关闭，评论行没有成功回调。共享回复分页、发送后刷新及失败重试，验收同一评论从两个入口展开都能加载完整回复并看到刚发送的内容。
- [ ] **全链路保留评论 ID 精度。** 列表已经优先使用字符串 ID 作身份，但播放器仍把回复 ID 转为 Int，详情部分交互也只读取数值字段。评论与父回复 ID 在读取、缓存、点赞、回复和去重中统一使用服务端字符串，覆盖超过双精度整数精确范围的 ID。

## P1 · 第三轮审查：消息来源与生命周期

- [ ] **消息发件人与稿件作者分开建模。** `MessagesView.linkedVideo` 把通知发件人的昵称和 MID 当作稿件作者，可能在详情显示错人，并让作者入口指向通知发送者。只从通知提取目标身份，用稿件详情补齐真实作者。验收第三方回复、点赞及 @ 通知。
- [ ] **消息跳转支持资源类型和评论锚点。** 当前只在通知字段中找 BV 号，缺少 BV 的动态、影视或评论通知没有原生跳转。按实际通知类型解析目标及评论 ID，共用详情入口。支持定位目标评论或回复，目标不可用时提供明确反馈；消息列表使用通知身份，无需按行号识别。
- [ ] **搜索分页按资源 ID 去重并校验身份。** 综合搜索的正版首屏做了去重，分类结果却直接追加；直播构造也会接受缺少房间 ID 的条目并生成 `live0`。在追加前验证 BV、季、房间、UP 主和专栏的必要身份，跨页去重并保持首个结果的位置。验收重复数据及空 ID，防止重复卡片和错误跳转。
- [ ] **明确关窗、重开与退出的播放行为。** 播放控制器和窗口状态由 App 持有，当前窗口入口没有显式的关窗清理。按用户的后台播放设置确定关窗后是否继续出声，统一结束播放与网关清理，保存最后进度。实机验证关窗、从 Dock 重开、退出应用以及设置窗口仍开着的组合场景。

## P1 · 第四轮审查：观看历史与元数据

- [ ] **修复观看历史误显示“0 播放”。** 云端历史到 Video 的转换没有传入播放量，通用模型把缺失值读成 0，卡片再直接显示。先确认接口实际字段，有数值时保留，缺失时省略；同一稿件如有可信的共享缓存可补齐。确实为零时仍显示零。验证云端历史、本机续播和旧版历史记录。
- [ ] **统一各入口的元数据字段与来源。** 核对首页、搜索、UP 投稿、收藏、稍后再看、动态、合集和消息的字段映射。覆盖普通视频播放量、收藏等来源的嵌套统计、直播在线或人气、影视更新信息，以及未知时长显示为 0:00 的问题。按内容类型定义指标，保留未知、真实零及有效值，并集中格式化单位和分隔符。用各入口的响应样例验证。
- [ ] **详情采用可信数据并回填共享缓存。** 普通详情已经获取详情接口数据，头图仍直接展示入口传来的作者和播放量。按资源 ID 合并可信的作者、封面、时长和统计数据，让已加载详情的同一视频在不同入口一致。缓存按需刷新和限并发，避免历史列表为每张卡片发一次详情请求。
- [ ] **观看历史界面突出观看信息。** 共用封面卡片，在历史场景优先展示可用的观看时间和续播进度。去掉与顶栏重复的“观看历史”，检查来源切换控件是否被顶栏遮住，以及迷你播放条展开时最后一行能否完整滚入可视区。

## P1 · 音轨提示与高级格式切换

- [ ] **修复只切音轨时显示视频画质的提示。** 当前成功提示始终取视频轨标签。切换开始、成功与失败都显示实际操作类型及目标，音轨显示对应码率、杜比全景声或 Hi-Res，画质显示对应分辨率或格式。
- [ ] **提升 HDR、杜比视界和高级音轨的取流与切换可靠性。** 核对普通视频和影视各自的真实播放清单与编解码标识；失效时按所选格式刷新一次播放地址并尝试合适的同格式候选。新播放项确认可用后再提交选中状态，失败恢复原视频轨与音轨，保留进度和暂停状态。防止连续切换、换集及后台恢复任务互相覆盖。用实际 HDR、杜比视界、杜比全景声和 Hi-Res 片源验证拉取、切换及回退，分别记录片源可用、解码就绪与设备实际输出。

### 本轮补充的播放故障

- [ ] **按视频和分集隔离上一组可播放轨道。** `lastPlayableVideo` 和 `lastPlayableAudio` 在 `stop()` 与打开新内容时没有清空，恢复又直接比较轨道 ID，存在把上一条视频的轨道用于新视频的路径。以当前媒体身份隔离回退记录，音频和视频成对保存。验证连续换视频、换分集、新内容首播即失败及仅切音轨失败。
- [ ] **切换成功以新播放项就绪为准。** `switchFailed` 目前在等待超时、任务取消和正常就绪时都可能返回同一结果，调用方会显示成功。区分就绪、失败、超时和已切到其他媒体。候选源准备失败时保留原播放项，对同格式重试设置总时限，并用旧请求迟到、连续选择及换视频场景验证提示与选中状态。
